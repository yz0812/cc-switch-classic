# Agent Note: 独立维护版仅发布 Windows x64 便携包

Status: implemented（已实施）

## Problem（问题）

独立维护分支已保留聚合模型 Fast 能力，但默认主分支仍未合入，原发布流程还要求 Windows 双架构安装器、Linux 与 macOS 产物及签名密钥。维护者明确要求合并到自己的主分支，并只打包一个 Windows 便携包。原下载和更新入口还指向来源仓库，会使用户拿到不同的代码版本。

## Decision（决定）

将包含上游 `09cdb5e2` 和原 Fast 修复 `9e0771d4` 的 `2a60f0fa` 快进合入 `main`，不重写原历史。独立维护以 `yz0812/cc-switch-classic` 的 `main` 为准，原分支继续保留。

发布流程仅使用 Windows x64 构建目标，执行 Tauri `--no-bundle` 生成程序，再由独立 PowerShell 脚本打包。唯一上传文件为 `CC-Switch-Classic-v{Classic版本}-Windows-Portable.zip`，根目录包含 `cc-switch.exe` 和 `portable.ini`。版本从生产常量读取，前后端一致，标签发布还校验标签版本；手动运行不把分支名用于文件名。

取消安装器、其他平台的发布构建、签名密钥依赖和更新清单生成。常规 CI 的跨平台源码检查继续保留。手动运行只产生 Actions artifact，推版本标签才创建正式 Release，合并主分支本身不发布版本。

应用内下载、便携更新和反馈入口改为自己的仓库，保留 README 对经典版来源和原始内核的署名。便携版通过 ZIP 下载更新，版本查询可回退 Releases API；不放宽已有签名验证，也不把便携 ZIP 冒充签名安装器。今后恢复安装版更新需要另行配置自己的签名与更新清单。

## Alternatives considered（考虑过的方案）

- 仅缩小构建矩阵：仍会要求 NSIS 和签名文件，不能满足仅便携包的要求。
- 编译全部平台后只上传一个包：浪费构建资源，未采用。
- 保留原下载入口：用户可能更新到不包含聚合 Fast 修复的来源版本，未采用。

## Consequences（收益与代价）

单平台发布降低构建成本，但不再提供其他架构或系统的下载包。Windows 运行环境需要 WebView2 Runtime，便携 ZIP 不安装它。

## Testing（验证）

本地对脚本使用独立临时目录和合成程序内容，确认 ZIP 内容完整、不混入相邻配置文件、缺失或空程序失败、非法版本失败、已有 ZIP 不被覆盖。此类夹具只验证打包逻辑，不证明真实程序可启动。

提交前运行维护文档检查、维护工具回归、`actionlint` 工作流检查，以及下载链接和版本相关的前后端检查。推送后以对应提交的手动 Release 工作流核验真实 Windows 编译和唯一 ZIP 产物；`publish` 作业应跳过。未创建版本标签，不把手动构建当作已发布版本。具体提交编号、运行链接和实际结果在本次交付记录中报告。

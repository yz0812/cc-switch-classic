# Agent Note: 独立维护版精简新增供应商入口

Status: implemented（已实施）

## Problem（问题）

完整预设库使新增页出现大量维护者不使用的供应商。维护者明确要求所有应用精简为各自官方登录和统一供应商入口，并指定 Codex 保留 OpenAI Official、xAI API 与 OAuth。原项目契约禁止只保留登录预设，本次根据独立维护版的明确产品要求修订该条。

## Decision（决定）

新增页通过共享上下文应用入口白名单，所有应用表单共用选择器，不逐个修改底层模板。各应用只保留自己的官方登录入口；跨应用托管登录不自动纳入。Hermes 的 Nous Research 是 API 模板而非登录入口，不因 category 为 official 而保留。

Codex 额外保留两个 xAI 预设。统一供应商沿用现有支持范围；不支持的应用不显示无效按钮。手动配置入口常驻，无官方登录的应用仍可添加自定义配置。

过滤发生在搜索、分组、计数之前，保留传入条目的对象与原始 ID。完整模板、配置投影、保存和编辑逻辑不变，已有供应商及聚合、Fast 能力继续保留。首页品牌已通过 REPO_URL 指向本维护仓库，不重复改写链接。

## Alternatives considered（考虑过的方案）

- 删除完整预设数组：会改变索引并破坏已有配置兼容，拒绝。
- 按账号登录分类统一过滤：会带入跨应用 Copilot 等入口，并漏掉 xAI API，拒绝。
- 在每个应用表单中复制过滤：容易遗漏特殊表单；采用新增页共享作用域，通用模板选择器仍可服务完整配置兼容测试。

## Consequences（收益与代价）

新增页更简洁。其他第三方服务需通过手动配置或支持的统一供应商添加。官方入口名称变化时需同步清单；基于真实预设的逐应用回归用于发现遗漏。此决定不扩展统一供应商后端支持范围。

## Testing（验证）

新增逐应用白名单、原始 ID 和对象引用、Codex 选择回调、统一供应商操作、无官方登录时手动配置及首页链接回归。新增页、策略与通用选择器共 61 项测试通过；表单载荷及 Kimi、DSH 新增页兼容测试亦通过。类型检查、改动文件格式检查、文档检查和前端生产构建通过。

真实浏览器检查宽窗、约 768 像素临界宽度与约 520 像素窄窗，四语言布局均无横向溢出；核对 Codex、Claude 和无官方登录的 Hermes。验证搜索焦点、隐藏模板无法被搜索找回、Esc 清空、xAI 原始 ID、统一供应商回调及首页链接。浏览器使用实际组件和合成选择回调，不调用真实账号；未执行桌面原生登录验收。后端和发布工作流本次未修改，不重复作为本地验证范围。
